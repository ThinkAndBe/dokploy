# AppHub 版本保留与回收（0.34.0）

用户在项目「代码与版本」查看每个版本的状态和保留原因。只有负责人或管理员可删除符合条件的版本，删除需说明原因和输入完整版本号，删除后进入回收站，可恢复原版本。

## 统一规则

- 代码：最近10个代码版本，或30天内的全部版本。满足任意一项即保留。
- 正式：每个正式服务当前版本及此前2个不同的成功版本；90天内的成功上线版本也保留。重复部署同一代码不会挤掉回退名额。
- 当前测试（含停止后可恢复）、最新代码、进行中的构建/部署/上线申请始终保留。
- 所有条件都不满足才可删除。引用按代码SHA判断，换版本名不能绕过。
- 历史版本首次纳管按首次发现时间获得观察期（默认30天），防止旧时间戳立即进入可删除范围；数量排序按代码提交时间。
- 管理员在项目页展开「管理员：统一保留规则」，修改当前组织所有项目的规则，必须填写原因。并发修改校验规则修订号。
- 旧手工保护迁移为90天额外保留。新特殊保留仅管理员操作，明确原因和1—365天期限；到期后仍检查全部自动规则。
- 普通用户不再看到保护/解除保护按钮，AI密钥不能删除、恢复、调整规则或登记正式部署。
- 当前不执行自动删除、Git历史清理、镜像清理、数据库/数据卷清理。回收版本入口不等于回收磁盘。

## 正式部署来源

平台上线流程根据测试构建的代码SHA、镜像摘要及成功上线方案自动核对，历史成功上线不永久阻止删除。等待处理的申请在存在成功上线记录后按正式版本保留规则判断。

平台自身由运维命令更新时，更新成功后必须登记。使用 scripts/apphub-record-deployment.py，管理员交互登录，提交 projectId、版本名、平台SHA、Swarm服务名、不可变镜像摘要及原因。后端核对实时服务镜像和更新状态后登记；操作幂等并记录审计。不要把密码写进脚本或Git。

示例（参数均为非敏感标识）：

```sh
python3 scripts/apphub-record-deployment.py --url https://apphub.erke.com --project PROJECT_ID --version v0.34.0 --sha PLATFORM_SHA --service apphub-production-console_apphub --image REGISTRY/IMAGE@sha256:DIGEST --reason '本次平台正式更新健康检查通过'
```

只登记健康检查通过的实际部署。运维须保存本地Git提交、平台SHA、构建镜像摘要、部署记录的对应关系。首次迁移前两版从现有交付证明补录；后续更新都执行上述登记，不再通过手动保护维持回退能力。

版本数据或仓库暂时无法核对时禁止删除并提示重试；不会推断为无引用。删除与构建、上线申请使用项目锁，避免刚进入回收站又被测试使用。权限在持锁后再次核查。
